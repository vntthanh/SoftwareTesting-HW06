## Gaps and ambiguities requiring review

1. For testing, treat `email`, `resetToken`, and `newPassword` as required because all three are necessary to perform the documented reset workflow.
2. Treat omitted required fields, `null`, wrong JSON types, malformed JSON, and non-object JSON bodies as invalid input. Extra and duplicate properties remain unspecified.
3. Use `application/json` for the request. Use `200 OK` as the normal successful-reset expectation, `400 Bad Request` for invalid request data. These are reviewed external HTTP assumptions because the SUT documents do not define the statuses.
4. FR-03 requires password confirmation, but the selected API request does not specify a confirmation field or another mapping.
5. FR-01 states email syntax for registration; FR-03 requires a registered email and OTP binding but does not state that the reset endpoint applies the FR-01 syntax validation rule.
6. The exact OTP expiry duration, comparison boundary, retry/attempt limit, rate limit, and replay response are absent.
7. FR-03 specifies a random six-digit OTP while SEC-07 says minimum six digits. This report treats FR-03’s exact six-digit workflow requirement as the more specific rule and does not broaden it.
8. No success status, error status, response media type, response header, response body, property, error structure, code, or message is documented.
9. No validation order or precedence is documented when multiple conditions are invalid.
10. The sources do not specify whether a successful reset logs the user in, returns or revokes tokens, revokes sessions, sends notification, or exposes any other side effect.
11. SEC-02 requires a valid JWT for security-sensitive APIs, but neither source classifies this public reset-password operation as JWT-protected. Authentication applicability is ambiguous and is not asserted here.
12. Password maximum length, whitespace treatment, Unicode treatment, character-counting method, reuse/history policy, and normalization are not specified.
13. Email case normalization and user-existence disclosure behavior are not specified.
14. Exact password persistence timing, OTP-consumption timing on success/failure, atomicity, and concurrency semantics are not specified.
